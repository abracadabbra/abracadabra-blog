## 前言

用 AI Agent 写代码，有没有觉得哪里不对劲？

每次新建一个 session，Agent 就跟失忆了一样——上次聊到哪了、哪些文件改过了、需求是什么，全忘了。你不得不把上下文再喂一遍，重复劳动，效率感人。

更难受的是，代码一多，Agent 对代码结构的理解就开始出错。它说"这个函数在 auth.py 里"，其实在 `middleware/auth.go`；它说"这两个模块没有依赖"，其实耦合得一塌糊涂。你不知道它是真懂还是在瞎猜。

今天介绍一套实战组合：**CodeGraph + Graphify + AgentMemory**，三者各管一层，配合起来给 AI Agent 装上完整的记忆系统。

## 问题：AI Agent 的三层短板

在说解决方案之前，先把问题拆清楚。AI Agent 的"失忆"其实分三层：

```
┌─────────────────────────────────────────────────────────────┐
│                    AI Agent 的三层短板                        │
├─────────────────────────────────────────────────────────────┤
│  ❌ 记忆层   — session 之间完全丢失，上次聊到哪全忘了         │
│  ❌ 知识层   — 概念关系靠猜，论文截图结论提取不出来           │
│  ❌ 代码层   — 代码结构理解靠运气，调用链经常出错             │
└─────────────────────────────────────────────────────────────┘
```

每个短板都对应一个专门解决它的工具：

| 层级 | 问题 | 工具 | 核心价值 |
|------|------|------|---------|
| 记忆层 | session 之间丢失上下文 | **AgentMemory** | 跨 session 记住项目状态 |
| 知识层 | 概念关系不清晰 | **Graphify** | 多模态输入 → 知识图谱 |
| 代码层 | 代码结构理解错误 | **CodeGraph** | 精确索引 + 调用链查询 |

## 方案：三层工具栈

```
┌─────────────────────────────────────────────────────────┐
│  AgentMemory  ────  记忆/上下文层  ───  "上次做到哪了"     │
│  （Agent 的大脑皮层，跨 session 记住项目上下文）            │
├─────────────────────────────────────────────────────────┤
│  Graphify     ────  知识/概念层  ───  "这些东西啥关系"    │
│  （把论文/截图/推文扔进去，自动抽取概念建图谱）              │
├─────────────────────────────────────────────────────────┤
│  CodeGraph    ────  代码/结构层  ───  "代码怎么组织的"    │
│  （索引代码库，提供精确的调用链/文件/上下文查询）            │
└─────────────────────────────────────────────────────────┘
```

三个工具各司其职，不重复：

- **CodeGraph** 不负责记忆，只负责代码结构
- **Graphify** 不负责代码，只负责概念关系
- **AgentMemory** 不负责检索，只负责上下文持久化

## 场景一：写代码时怎么协同

**目标**：让 Agent 精准理解代码结构，写出准确的代码示例

### 问题

写技术博客最怕什么？代码示例写错。函数名错了、路径错了、调用顺序错了——读者照着抄，结果跑不通。这是没有结构索引的 Agent 最大的隐患。

### 工具组合：CodeGraph × AgentMemory

```
┌──────────────────────────────────────────────────────────┐
│  场景一：写代码时                                         │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  AgentMemory ──► 记住当前在写哪个项目、哪个模块             │
│       │                                                  │
│       └──► CodeGraph ──► 索引代码，提供准确的调用链        │
│                          输出准确的代码示例                 │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### 实战流程

**第一步**：在项目里初始化 CodeGraph

```bash
cd /root/gold-agent
codegraph init
codegraph index
```

**第二步**：启动 AgentMemory（让 Agent 记住当前项目上下文）

```bash
agentmemory connect hermes
# 告诉 Agent：当前项目是 gold-agent，专注后端模块
```

**第三步**：写文章时，Agent 查代码结构

```bash
# 查调用链——准确知道谁调谁
codegraph trace "predict_gold_price"

# 查文件关系——准确知道模块怎么组织
codegraph files

# 查函数上下文——输出代码示例时有完整依据
codegraph context "calculate_support_resistance"
```

### 效果对比

| | 没有工具 | 有 CodeGraph + AgentMemory |
|---|---|---|
| 代码示例准确性 | ❌ 经常猜错 | ✅ 索引结果，精确可靠 |
| 调用链 | ❌ "应该调 A" | ✅ `A → B → C`，真实路径 |
| 上下文保持 | ❌ session 结束全丢 | ✅ AgentMemory 记住 |
| 重复解释成本 | 高，每次重新介绍项目 | 零，记忆层已建立 |

## 场景二：做研究时怎么协同

**目标**：把散落的论文、截图、推文变成可查询的知识网络

### 问题

写 AI Agent 相关文章，需要大量研究素材——Karpathy 的推文、论文里的架构图、项目 README、别人的踩坑贴士。这些东西散落在不同地方，Agent 每次都得重新"理解"一遍。

### 工具：Graphify

Graphify 的核心思路来自 Karpathy 的 `/raw` 文件夹——把任意格式的研究素材扔进去，它用 Claude Vision 提取概念和关系，自动生成一张知识图谱。

```
┌─────────────────────────────────────────────────────────┐
│  Graphify 输入                                          │
├─────────────────────────────────────────────────────────┤
│  📄 论文 PDF（attention is all you need）               │
│  📸 架构截图（从别人博客里截的）                         │
│  🐦 推文截图（Karpathy 的 agent 思考）                  │
│  📝 笔记文件（自己的随笔）                               │
│  🖼️ 白板照片（手画的流程图）                            │
└─────────────────────┬───────────────────────────────────┘
                      │ Claude Vision 多模态理解
                      ▼
┌─────────────────────────────────────────────────────────┐
│  Graphify 输出                                          │
├─────────────────────────────────────────────────────────┤
│  📊 graph.html        交互式图谱（可点击、可搜索）        │
│  🗂️ obsidian/         Obsidian 笔记库（双链笔记）         │
│  📖 wiki/              AI 可读的 Wiki（Agent 导航）        │
│  📋 GRAPH_REPORT.md   关键节点 + 意外联系 + 建议问题      │
│  🗃️ graph.json        持久化图谱（下次直接查，不用重跑）  │
│  💾 cache/            SHA256 缓存（只重跑变化的文件）      │
└─────────────────────────────────────────────────────────┘
```

### 实战流程

**第一步**：建一个 `raw` 研究文件夹

```bash
mkdir -p ~/research/agent-memory
cd ~/research/agent-memory

# 扔进去
# - attention.pdf
# - karpathy-agent-tweet.png
# - swin-transformer-arch.jpg
# - my-notes.md
```

**第二步**：跑 Graphify 建图谱

```bash
graphify .
# 输出 graph.html，用浏览器打开看交互图谱
# 输出 obsidian/ 目录，用 Obsidian 打开做双链笔记
```

**第三步**：写文章时查询

```bash
# 问关联问题
graphify query "attention 机制和优化器有什么关系"

# 查路径
graphify path "Memind" "Insight Tree"

# 建 AI 可读的 Wiki（方便 Agent 导航）
graphify . --wiki
```

### 效果对比

| | 没有 Graphify | 有 Graphify |
|---|---|---|
| 论文理解 | 每次重新读一遍 | 一次建图谱，随时查 |
| 截图/推文 | 无法处理 | Claude Vision 提取概念 |
| 概念关联 | 人脑来找 | 自动生成关联边 |
| 知识复用 | 用完就忘 | graph.json 持久化 |

## 场景三：持续创作时怎么协同

**目标**：跨多天、多 session 完成一篇长文创作

### 问题

写一篇《多 Agent 协作》系列的深度文章，可能要花一周。今天写了第一部分，过两天打开，Agent 不记得：

- 之前确定了什么方向
- 哪些模块已经写过了
- 还差哪些场景没覆盖
- 需求改了几版，最终结论是什么

没有记忆，每次重新开始，效率大打折扣。

### 工具组合：AgentMemory × CodeGraph × Graphify

```
┌──────────────────────────────────────────────────────────┐
│  场景三：持续创作时                                       │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  AgentMemory ──► 记住创作上下文：写到哪了、下一步做什么    │
│       │                                                  │
│       ├──► CodeGraph ──► 写代码示例时查准                 │
│       │                                                  │
│       └──► Graphify  ──► 概念解释时查知识图谱            │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### 实战流程

**第一天**：建立创作上下文

```
用户：我要写一个系列文章，《AI Agent 工作流工具栈》
目标：覆盖 CodeGraph、Graphify、AgentMemory
AgentMemory 自动记住这个目标
```

**第二天**：

```
AgentMemory 读到上下文：用户正在写《AI Agent 工作流工具栈》，
                        第一篇讲三层工具栈，这是第二篇
                        已完成：场景一（代码协作）
                        待完成：场景二（知识研究）、场景三（持续创作）

Agent 自动进入续写状态，不需要用户重新说明
```

**写作过程中**：

```bash
# 写代码场景时——CodeGraph 查准
codegraph context "某个函数"

# 写研究场景时——Graphify 查概念
graphify query "多 Agent 通信模式有哪些"

# 写完一段——AgentMemory 自动更新上下文
#   "场景二已写完，待写场景三 + 总结"
```

## 三层工具协作总览

三个工具不是孤立用，而是形成一条完整的数据流：

```
研究素材（论文/截图/推文）
        │
        ▼
   Graphify ──► 知识图谱（graph.json）
        │                 │
        │          ┌──────┴──────┐
        │          ▼             ▼
        │    obsidian/        wiki/
        │   （双链笔记）    （Agent可读）
        │
代码库（项目目录）
        │
        ▼
   CodeGraph ──► 代码索引（.codegraph/）
        │                 │
        │          ┌──────┴──────┐
        │          ▼             ▼
        │     codegraph      codegraph
        │     query          context
        │   （查调用链）     （查上下文）
        │
创作上下文（AgentMemory）
        │
        ▼
   跨 session 记忆（自动持久化）
        │
        ├──► "上次写到场景二"
        ├──► "CodeGraph 索引已建立"
        └──► "Graphify 图谱已就绪"
```

### 使用优先级建议

根据创作场景不同，优先级也不同：

| 场景 | CodeGraph | Graphify | AgentMemory |
|------|-----------|----------|-------------|
| 写代码示例为主 | ⭐⭐⭐ 必用 | ⭐ 备选 | ⭐⭐ 必用 |
| 做调研/研究为主 | ⭐ 备选 | ⭐⭐⭐ 必用 | ⭐⭐ 必用 |
| 持续长文创作 | ⭐⭐ 常用 | ⭐⭐ 常用 | ⭐⭐⭐ 必用 |
| 快速单次任务 | 可选 | 可选 | ⭐ 推荐 |

## 总结

CodeGraph + Graphify + AgentMemory 这三个工具，每个都解决一个具体的短板：

- **CodeGraph** → 代码结构的"精准地图"，让 Agent 不再瞎猜调用链
- **Graphify** → 知识网络的"智能抽认卡"，让散落的素材变成可查询的图谱
- **AgentMemory** → 创作过程的"记忆宫殿"，让跨 session 创作不断片

三者叠加，AI Agent 从"每次从零开始的对话机器"，进化成"有记忆、有知识、有结构理解的专业助手"。

这不是三个独立工具的简单堆叠，而是一套**按层分工、相互增强**的工作流。记住这个分工原则就好：

> **记忆靠 AgentMemory，知识靠 Graphify，代码靠 CodeGraph。**

如果你也在用 AI Agent 写代码/写文章，不妨试试这套组合。
